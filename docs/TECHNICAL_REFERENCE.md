# Personal Journal 1.3 — Technical Reference

目标：Project Zomboid Build 42.20；原生契约实测版本：42.20.4。
Mod ID `LegacyJournal`，Workshop `3788037313`，build `1.3-native-actions-release`。
当前唯一正常开发/回滚基准为 1.3；上一正式版仅作紧急兜底，现称 1.2，历史标识为 1.02。
公开版本号与物品数据格式独立；本次仍为 `LJ_version=6`。

## 关键架构

只使用原版 `Base.Diary1`、`Base.Diary2`，不新增物品、配方或外部依赖。
原版负责菜单、转移、动作队列、网络动作计时、动画及字段同步；Mod 负责知识差值、
账号继承权限、内容页数、恢复语义和本地显示。

| 模块 | 主要职责 |
| --- | --- |
| `legacyjournal_shared.lua` | 数据模型、身份、快照、差值、页数、检查点、写入与恢复 |
| `legacyjournal_actions.lua` | 原生动作开始/取消/完成与权威数据校验 |
| `legacyjournal_client.lua` | 堆叠菜单、原版转移、动作入队及恢复字段补齐 |
| `legacyjournal_server.lua` | 无页码检查点提示和恢复结果分批下发 |
| `legacyjournal_presentation.lua` | 可见日志本地化名称，覆盖取消后的迟到字段同步 |
| `legacyjournal_skillbook_compat.lua` | 42.20.4 瞬间阅读技能书的局部兼容 |

多人流程为原生网络 TimedAction → 服务端计划/校验 → 原生 `complete` → 共享写入或恢复
函数 → 原版字段同步。旧的自建 `begin`、一次性令牌和 `commit` 消息协议已经撤除。
客户端不上传知识快照，也不决定保存页码；自定义检查点消息只提示服务端检查当前动作。
单人和多人共用知识规则，不维护两套恢复算法。

## 数据与恢复不变量

实体日记本的 `modData` 保存作者、时间、技能 XP、配方、技能书页数和实际倍率区间、
永久奖励媒体状态。只接受精确 v6，不猜测迁移无版本、损坏或未来格式。

- 作者优先绑定服务器认证 username；旧数据缺少账号字段时保留人物名兼容回退。
- XP 保存历史最高值；恢复只补足比例目标以下的缺失 XP，不降低已有进度。
- 配方只补当前未知项，死亡后新学会的配方不会被覆盖。
- 技能书恢复只提高已读页数和当前等级适用倍率；文盲不恢复技能书状态。
- 部分早期 v6 日志缺少精确技能书快照，允许一次写入补齐；不属于数据格式迁移。
- 只记录有永久技能、XP 或配方奖励的 CD/VHS；按整段媒体补齐其已知行，纯娱乐媒体忽略。
- 配方、书籍和媒体使用稳定排序与确定性恢复配额，重复阅读不能重抽或逐次刷满。
- 分类开关关闭只停止该类别记录/恢复，不清除既有记录。

## 页数、耗时与中断

内容单位按技能、XP、配方、技能书和媒体差值累计，基础页数直接计算：

```text
pages = max(1, ceil(units * 7 / 1000))
```

只在最后取整，不先算旧整数页数再乘 0.70。阅读复用原版 `ISReadABook.getDuration`，
保留阅读特质、眼镜和坐地影响；正式写入恢复内容页数对应的原有时间公式，再应用独立
沙盒写入倍率，不固定 30 秒。原版管理员瞬间动作设置仍可直接完成动作。

检查点绑定实体、人物和动作。服务端读取原生动作进度，单调保存完整页数；未跨过一页时
不保存。取消后续作从最近完整页开始，因此可能略退一点，不是精确百分比续作。
两次动作之间内容变化可重算总页数并保留已有绝对完成页；成功完成后清除续作字段。
旧无模型检查点按完成比例映射；未知显式未来模型不猜测。当前动作提交仍复核状态签名。

## 显示与兼容边界

显示层在既有容器刷新时缓存已写日志名称，并在原生可见行绘制边界仅修复缓存日志的名称
偏移；这也覆盖取消后迟到的原版字段包。稳定帧不重复翻译或改名，没有全局 Tick 扫描。
客户端只做本地显示，不能反向同步旧物品字段覆盖服务端新记录。

写入禁用说明使用“无内容可写 / 無內容可寫 / Nothing to write”；阅读禁用复用原版
`ContextMenu_EmptyNotebook`。空白本首次写入不提前变成已命名日志。
技能书瞬间阅读兼容补丁限定已验证的 42.20.4，不能在游戏升级后无证据扩大范围。
日志仍依赖实体物品和原生保存系统，不承诺抵御修改引擎或存档的客户端。

内部单一 NUC runner 执行 16 组行为测试、6 个 Lua 解析、三语目录、载荷边界和原生源码
指纹检查；公开仓库不包含内部测试工具或发布凭据。离线通过不替代实际多人验收。
正式写入公式已与实际上一正式源码作 108 组一致性对照；核心记录恢复函数未改变。

项目进入冷维护：仅处理游戏兼容、安全/数据损坏、明确性能回退或所有者明确提出的需求。
后续修复从不可变 1.3 基准恢复到新树，先检查再修改，不在正式运行目录开发。
更新磁盘不等于运行中 Lua 已加载；部署、重启、世界恢复是分别授权的操作。
